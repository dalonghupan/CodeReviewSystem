## 1 项目背景与现存问题
当前团队代码评审完全依托GitLab、Gitee原生MR功能开展，评审沟通依托即时聊天工具线下完成，存在诸多不符合CMMI3标准化管控要求的问题：
1. 评审流程无标准化线上闭环，评审意见零散、无法统一留存归档；
2. 代码缺陷缺少统一台账记录，缺陷数量、修复效率、技术债务无法量化统计；
3. 缺少自动化代码质量门禁，高危漏洞依赖人工肉眼排查，漏审风险高；
4. 仓库权限、评审人员权限混乱，缺少多租户数据隔离能力；
5. 评审超时无预警催办机制，大量评审单据积压，拖慢版本迭代进度。

为实现研发过程标准化、代码质量可度量、评审流程全链路可追溯，打造私有化部署、云原生架构、支持后期AI评审扩展的企业级统一代码评审平台，正式启动本项目建设。

## 2 项目定型最优技术架构
### 前端技术栈
React 19 + Next.js（App Router）+ Shadcn/ui + Monaco Editor + TanStack Query
### 后端技术栈
Golang 1.24 + Kratos v2 微服务框架；服务间gRPC二进制通信，对外网关转换为HTTP/2 JSON接口
### 网关与认证
Apache APISIX 云原生网关、Keycloak（OIDC/OAuth2.1）统一身份认证
### 消息事件总线
RocketMQ 5.x 事务消息+延迟消息，全业务事件驱动异步解耦
### 中间件与存储
PostgreSQL 17 主从读写分离集群、Redis7.2 分片集群、Elasticsearch8.x冷热分离检索集群、分布式MinIO对象存储
### 云原生运维底座
Kubernetes 1.31 + ArgoCD（GitOps持续部署）；可观测体系：Prometheus+Grafana监控、Loki日志归集、Jaeger全链路追踪

## 3 CMMI量化项目目标
1. 流程目标：代码评审「发起-指派-批注-复审-通过-归档」全流程100%线上标准化闭环；
2. 质量目标：高危代码缺陷人工漏审率降至0%，所有评审单据闭环完成率100%；
3. 效率目标：自动化扫描前置拦截代码问题，人工重复性评审工作量降低40%；
4. 度量目标：输出日、周、月度代码质量报表，实现缺陷数量、修复时效、技术债务量化展示；
5. 合规目标：全流程文档可追溯，关键操作日志留存不少于6个月，顺利通过CMMI3过程审计。

## 4 项目包含范围 & 排除范围
### 包含范围
1. GitLab/Gitee/GitHub三方平台OAuth2.1授权接入，仓库、分支、MR、Commit数据自动同步；
2. MR一键发起评审、代码Diff分栏高亮展示、行级评论批注、多轮复审管控；
3. Keycloak对接LDAP/企业微信单点登录，多租户隔离、RBAC精细化权限管控；
4. RocketMQ实现多渠道消息推送、评审到期预警、超时周期性催办；
5. 评审缺陷自动归集生成台账，质量指标统计可视化、报表导出归档；
6. 对接SonarQube搭建代码质量门禁，高危漏洞未修复禁止评审放行；
7. 全套云原生监控、日志、链路追踪体系，容器化自动化部署运维。

### 排除范围
1. 不自主研发静态代码扫描内核，仅对接成熟SonarQube服务；
2. 系统仅限企业内部私有化部署使用，不面向公网对外商用；
3. 一期不落地AI自动代码评审能力，仅预留标准化扩展接口，后期迭代新增。
