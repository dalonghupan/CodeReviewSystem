## 1 总则
### 1.1 设计目的
基于已定需求基线，完成系统整体架构分层、微服务拆分、网络通信、数据存储、中间件集成、第三方对接的高层方案设计；明确各模块边界与依赖关系，为后续详细设计、编码开发提供架构约束，规避架构性缺陷，满足可扩展、高可用、可运维、可审计的CMMI3要求。
### 1.2 设计约束
1. 严格遵循已定最优技术栈，不得随意更换基础框架与中间件；
2. 整体采用事件驱动+微服务架构，禁止出现单体式耦合改造；
3. 所有跨服务交互禁止直连数据库，统一走gRPC或RocketMQ消息；
4. 生产环境必须实现多副本集群部署，杜绝单点故障。
### 1.3 整体七层云原生架构分层（自上而下）
1. 接入层：CDN + Nginx静态资源服务 + Next.js前端应用
2. 网关安全层：Apache APISIX网关 + Keycloak统一认证授权服务
3. 业务微服务层：6组Kratos Golang微服务（核心业务载体）
4. 事件总线层：RocketMQ 5.x，承载全系统异步事件解耦
5. 支撑中间件层：Redis集群、Elasticsearch检索集群、定时调度能力
6. 持久化存储层：PostgreSQL主从读写分离集群、MinIO分布式对象存储
7. 可观测运维层：监控、日志、链路追踪一体化平台

## 2 微服务拆分概要设计（高内聚、低耦合）
### 2.1 git-adapter 仓库适配服务
核心职责：三方Git平台接口对接、OAuth授权生命周期管理、项目/分支/MR数据同步、第三方接口限流防护、敏感文件过滤校验；
对外依赖：Redis（接口限流计数、授权Token缓存）、PostgreSQL（仓库绑定配置）、RocketMQ（发布代码拉取事件）；
禁止依赖其他业务服务数据库，仅通过消息与gRPC对外交互。

### 2.2 cr-core 评审核心服务
核心职责：评审单据生命周期管理、状态流转控制、代码行评论管理、复审权限校验、Sonar门禁结果校验放行控制；
依赖：iam-service（gRPC权限校验）、git-adapter（MR基础数据查询）、PostgreSQL（评审单、评论主表）、Redis（Diff结构化数据缓存）、RocketMQ（发布单据变更事件、缺陷统计事件）。

### 2.3 quality-stat 质量统计服务
核心职责：消费MQ事件归集缺陷数据、多维度质量指标计算、月度离线统计任务、报表生成与PDF/Excel渲染、报表文件存入MinIO；
依赖：PostgreSQL（缺陷台账、统计结果）、MinIO（报表存储）、Elasticsearch（历史评审日志检索）、RocketMQ（消费单据完结事件）。

### 2.4 message-push 消息推送服务
核心职责：统一消费各类通知事件，按照渠道配置分发站内信、企业微信、邮件消息；统一封装多第三方推送适配器，新增渠道仅新增适配器，不改动业务逻辑；
依赖：PostgreSQL（用户消息偏好配置）、RocketMQ（消费通知事件）。

### 2.5 job-scheduler 定时任务服务
核心职责：仓库增量同步触发、过期临时缓存清理、每日离线统计任务执行、数据库数据定时对账修复消息不一致问题、Token自动轮换刷新；
依托K8s CronJob+内部任务管理器实现，不额外引入定时任务中间件。

### 2.6 iam-service 身份权限租户服务
核心职责：租户管理、用户角色维护、RBAC权限资源定义、对接Keycloak完成账号同步、提供统一权限校验gRPC接口；
依赖：PostgreSQL（租户、账号、权限关系表）、Keycloak服务。

## 3 服务通信协议概要设计
1. **内网微服务之间调用（同步）**：统一使用 gRPC + Protobuf 二进制协议
- 优势：序列化体积小、传输速度快、自带服务发现、超时控制、自带拦截器便于统一埋点日志与链路追踪；
- 统一约定错误码、请求超时时间、拦截器规范。
2. **前端对外访问（同步）**：HTTP/2 + JSON REST接口
- 由APISIX完成反向代理、协议转换，将前端http请求转发并转换为后端对应gRPC调用，后端服务不直接暴露公网端口；
3. **全系统异步通信（解耦）**：RocketMQ 消息队列
- 业务触发事件发送消息，对应消费服务异步处理；
- 关键业务创建操作使用**事务消息**保证数据库与消息一致性；
- 提醒预警类使用**延迟消息**实现定时任务效果。

## 4 数据库概要设计（PostgreSQL 17 主从架构）
### 4.1 部署模式
一主多从，写请求全部命中主库，查询请求路由至从库实现读写分离；开启逻辑备份+定时全量备份。
### 4.2 核心业务表分类概要
1. 租户与权限类：租户信息表、账号角色表、权限资源表、Keycloak账号映射表
2. 仓库配置类：Git授权记录表、绑定仓库表、仓库黑白名单表、敏感文件配置表
3. 评审业务类：评审主单表、代码行评论表、复审记录表、Sonar扫描关联表
4. 质量台账类：缺陷记录表、月度统计数据表
5. 系统支撑类：用户消息配置表、系统操作日志表、定时任务执行记录表
### 4.3 关键存储策略
1. 动态评审检查项、自定义门禁规则使用JSONB字段存储，无需频繁变更数据表结构；
2. 代码评论表按月进行自动分表，千万级评论数据分散存储，避免单表过大造成查询性能衰减；
3. 所有数据表建立必要索引：MR编号、评审单ID、租户ID、时间范围索引。

## 5 Redis集群缓存概要设计（Redis7.2分片集群）
### 5.1 缓存分类与用途
1. 热点基础缓存：仓库基础信息、用户权限信息、租户配置信息，减少重复查询数据库；设置合理过期时间，兼顾实时性与性能；
2. 代码Diff结构化缓存：后端解析完成的代码行映射数据，大文件解析结果缓存复用，避免重复调用Git接口解析；
3. 分布式业务锁：创建评审单锁，防止同一MR重复生成多条评审单据；
4. 第三方限流计数器：统计Git接口调用频次，触发阈值后限制调用，防止被Git平台封禁接口；
5. 临时会话缓存：短期临时授权状态缓存。
### 5.2 缓存淘汰策略
采用Redis自带淘汰机制，业务临时数据统一设置TTL自动过期，后台定时任务清理无效僵尸key，减轻内存占用。

## 6 Elasticsearch检索概要设计
1. 存储内容：历史评审全量操作日志、缺陷明细日志、系统运行日志；
2. 用途：支持按租户、时间、评审单号进行全文检索，用于问题追溯、CMMI审计日志查询；
3. 冷热分离架构：近期热数据高性能节点存储，数月前冷数据转入低成本存储节点，节约资源。

## 7 MinIO对象存储概要设计
存储内容：导出的Excel/PDF质量报表、用户上传附件、系统导出归档文档；
按照租户划分独立存储桶，桶权限隔离，跨租户无法访问对方文件，配合生命周期策略自动清理过期临时文件。

## 8 第三方集成概要设计
所有外部第三方统一采用**适配层模式**接入，业务核心代码零侵入：
1. Git三方平台适配层：统一封装GitLab/Gitee/GitHub接口，新增平台仅扩展适配器；
2. SonarQube扫描适配层：统一解析扫描结果，自定义门禁规则由业务层配置控制；
3. 消息推送适配层：企业微信、邮件各自独立适配器；
4. Keycloak身份适配层：统一封装登录、账号同步接口。

## 9 安全架构概要设计
1. 传输安全：前端到网关HTTPS，服务内部容器网络私有隔离通信；
2. 认证安全：网关完成JWT令牌有效性校验，未登录请求直接拦截；
3. 权限双层校验：网关鉴权 + iam-service业务数据权限校验；
4. 接口安全：APISIX限流、IP黑白名单、请求大小限制；后端所有入参强制校验防注入；
5. 数据安全：密钥配置存入K8s Secret，禁止硬编码到代码与配置文件；敏感数据脱敏存储、脱敏返回。

## 10 可观测架构概要设计
1. 指标监控：Prometheus采集所有服务指标，Grafana制作业务大盘、告警面板；
2. 日志系统：Promtail采集容器日志推送至Loki，支持按服务、TraceID、关键词检索；
3. 链路追踪：Jaeger采集全链路调用轨迹，每个请求全局唯一TraceID，贯穿网关、所有微服务、MQ消费；
4. 告警能力：服务异常、MQ消息堆积、接口错误率飙升、数据库负载过高自动推送告警通知。

## 11 部署架构概要（K8s + ArgoCD GitOps）
1. 环境隔离：开发环境、测试环境、预发布环境、生产环境四套独立K8s集群完全隔离；
2. 发布模式：代码流水线构建镜像→配置仓库更新镜像版本→ArgoCD自动感知配置变更，执行滚动发布；
3. 灰度发布：新版本先部署少量Pod灰度验证，无异常再全量更新；发布故障自动回滚至上一个稳定镜像版本；
4. 中间件全部容器化部署，配置使用ConfigMap、密钥使用Secret统一管理。
