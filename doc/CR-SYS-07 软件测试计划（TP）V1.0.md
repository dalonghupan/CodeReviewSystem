## 1 总则
### 1.1 编制目的
统一规划项目全周期测试阶段、测试类型、测试范围、环境资源、用例管理、缺陷管理、准入准出标准、测试交付物，保障所有功能、性能、安全需求得到充分验证；区分研发自测、集成测试、系统测试、性能安全测试、UAT验收测试，实现测试活动可管控、可追溯、可量化，支撑质量基线落地，规避线上故障。
### 1.2 测试适用范围
前端页面所有交互逻辑、6个Golang微服务接口、RocketMQ消息异步业务逻辑、第三方对接（Git平台、SonarQube、Keycloak）、Redis缓存逻辑、PostgreSQL数据读写、权限隔离、定时任务、报表导出全模块。
### 1.3 测试约束
1. 测试用例必须关联SRS唯一需求编号Fxx/Nxx，做到需求全覆盖；
2. 测试环境、预发布环境、生产环境物理隔离，禁止混用数据与配置；
3. P0/P1缺陷未清零，不得流转至下一测试阶段；
4. 所有测试执行记录、日志、报告统一归档，满足CMMI审计要求。

## 3 测试环境整体规划（4套独立K8s环境完全隔离）
### 3.1 开发环境（DEV）
用途：研发本地调试、前后端联调、开发自测
部署内容：精简版中间件，数据库可随时重置清理，研发拥有读写权限
准入：开发阶段全程使用，不做正式测试

### 3.2 测试环境（TEST，正式测试执行环境）
用途：集成测试、系统功能测试、第一轮性能测试、安全扫描
配置：完整复刻预发中间件集群（PostgreSQL主从、Redis集群、RocketMQ、ES、MinIO、Keycloak、APISIX、SonarQube）；数据定期脚本重置，避免历史脏数据影响用例执行；测试账号统一管理，权限受控，研发仅拥有查看权限，禁止手动修改数据库数据。

### 3.3 预发布环境（STAGING）
用途：UAT用户验收测试、第二轮真实量级压力复测、上线前最终安全校验
配置：硬件配置、中间件版本、配置参数与生产环境1:1一致；使用脱敏模拟业务数据，禁止导入真实生产业务数据；发布流程与生产完全一致，采用GitOps灰度发布。

### 3.4 生产环境（PROD）
用途：正式对外提供服务；仅做上线后冒烟测试，不再开展完整功能测试；上线7天持续监控线上指标。

## 4 测试阶段划分、各阶段任务、准入/准出条件、交付物
### 阶段1：单元测试与研发自测（研发执行，测试监督抽检）
1. 测试主体：后端开发、前端开发自行完成
2. 测试内容：
   - 后端：Service核心业务方法、数据层CRUD、MQ生产消费逻辑、工具类函数单元测试，覆盖率≥85%
   - 前端：核心状态管理、请求封装、权限判断、编辑器工具方法单元测试，核心逻辑覆盖率≥75%
   - 接口Postman自测：所有对外接口正向、异常入参自测
3. 准入条件：对应模块编码完成，代码提交至测试分支
4. 准出条件：单元测试达标、自测无P0/P1缺陷、自测报告提交至测试组与SQA备案
5. 交付物：单元测试代码、自测用例清单、自测结果说明文档
6. 流转：全部模块自测完成，方可进入集成测试

### 阶段2：集成测试（接口联调测试）
1. 测试主体：测试工程师+前后端开发配合
2. 测试内容：微服务gRPC跨服务调用连通性、MQ消息收发一致性、前后端接口字段匹配、第三方接口联调（Git拉取MR、Sonar扫描、推送消息）；重点验证分布式锁、事务消息、消息幂等性、跨服务异常熔断逻辑
3. 准入条件：所有服务自测完成，测试环境完整部署最新版本
4. 准出条件：服务调用无连通故障，消息无丢失、重复消费异常；集成类缺陷全部修复闭环
5. 交付物：集成测试用例、集成测试问题记录表、集成测试小结报告

### 阶段3：系统功能测试（核心测试阶段，多轮迭代）
1. 测试主体：专职功能测试工程师
2. 测试范围：覆盖SRS全部F开头功能性需求，包含：登录授权、租户管理、仓库授权、评审单创建流转、行评论管理、复审控制、Sonar门禁拦截、消息通知、缺陷台账、数据大盘、报表导出、黑白名单、敏感文件屏蔽、定时任务执行效果；包含正常流程、异常流程、边界值、非法操作反向用例
3. 执行轮次：
   - 第一轮：全覆盖基础功能，提交全部缺陷
   - 第二轮：缺陷回归+遗漏场景补充测试
   - 第三轮：全量回归，验证整体流程连贯性
4. 准入条件：集成测试通过，测试环境版本稳定
5. 准出硬性条件：P0、P1缺陷清零；P2缺陷100%修复；P3缺陷完成登记，制定迭代修复计划；功能用例执行通过率100%
6. 交付物：完整测试用例库（绑定需求编号）、缺陷管理台账、多轮系统测试报告

### 阶段4：专项性能测试 + 安全测试
#### 4.1 性能压力测试
测试场景：50用户并发登录、批量创建评审单、万行代码Diff加载、批量导出月度报表、高峰期消息推送；监控接口响应时间、服务器CPU/内存、数据库QPS、Redis命中率、MQ堆积量；必须满足SRS非功能性能指标。
#### 4.2 安全测试
测试内容：越权跨租户访问、SQL注入、XSS脚本注入、接口暴力请求限流、Token伪造篡改、敏感信息泄露、后端错误栈对外暴露、Git Token泄露风险、文件上传漏洞扫描
1. 准入条件：系统功能测试全部通过
2. 准出条件：性能指标全部达标；高危、中危安全漏洞全部修复；低危漏洞给出优化方案
3. 交付物：性能测试报告、安全渗透测试报告

### 阶段5：UAT验收测试（业务用户验收测试）
1. 测试主体：各业务线研发代表、最终使用人员，测试人员协助记录问题
2. 测试内容：模拟真实日常使用流程，完成完整从绑定代码仓库→发起MR→创建评审→代码批注→门禁校验→归档看缺陷报表全链路试用
3. 准入条件：性能安全测试通过，预发布环境部署完毕
4. 准出条件：验收核心问题全部修复，业务负责人签署UAT验收确认单，无新增P0/P1缺陷
5. 交付物：UAT验收问题清单、验收确认签字文档

### 阶段6：上线冒烟测试 & 线上试运行监控测试
1. 上线完成后运维+测试执行核心接口冒烟测试，验证基础服务可用；
2. 上线连续7天，依托监控平台持续测试系统运行稳定性、错误率、告警情况；
3. 交付物：上线冒烟测试记录表、7天线上运行质量监控简报

## 5 测试用例管理规范
1. 用例统一字段：用例ID、关联需求编号、所属模块、前置条件、操作步骤、预期结果、实际结果、测试状态、测试人员、执行时间；
2. 用例分为正向用例、反向异常用例、边界用例三大类，关键业务边界必须覆盖（过期截止时间、黑名单仓库、超大Diff文件、空MR、已归档单据重复操作）；
3. 用例随同需求基线一同评审，评审通过后方可执行测试；需求发生变更，对应用例同步更新并重新评审；
4. 用例统一归档管理，作为CMMI审计必备资产。

## 6 缺陷管理规范（沿用SQA缺陷分级：P0致命、P1严重、P2一般、P3轻微）
### 6.1 缺陷提报要素
缺陷标题、所属版本、所属模块、重现步骤、预期结果、实际结果、截图/日志附件、缺陷等级、发现人、提交时间、处理人
### 6.2 缺陷生命周期
新建→指派开发→开发修复→提交复测→测试验证通过关闭 / 验证不通过退回重修复；已关闭缺陷出现复现，升级对应缺陷等级重新处理
### 6.3 修复时效约束
- P0：2小时修复复测关闭，测试暂停阻塞
- P1：24小时内修复完成，本轮测试结束前必须关闭
- P2：本轮测试周期内全部修复关闭
- P3：UAT验收前统一全部修复完毕
### 6.4 缺陷拒绝准则
开发不得无故驳回合理缺陷；存在争议由测试负责人+SQA共同裁定最终等级与处理方案。

## 7 测试优先级与风险测试点（重点加码测试）
1. 跨租户权限隔离（最高优先级，防止数据泄露）
2. RocketMQ事务消息与消息幂等性（避免重复生成评审单、重复推送消息）
3. Sonar质量门禁拦截逻辑（漏洞校验是否生效，不可绕过）
4. 超大代码Diff前端渲染性能与后端解析耗时
5. 评审单状态流转约束，禁止非法跳转状态
6. Git授权Token自动刷新、过期失效处理逻辑
7. 定时对账任务修复消息与数据库数据不一致问题

## 8 测试风险及应对措施
| 风险描述 | 风险等级 | 应对方案 |
| ---- | ---- | ---- |
| 第三方Git/Sonar接口不稳定，导致测试无法进行 | 中风险 | 提前准备模拟Mock服务，第三方不可用时切换Mock完成内部逻辑测试，接口恢复后再做真实联调 |
| 测试环境数据混乱，干扰用例执行结果 | 中风险 | 每轮测试开始前自动执行脚本重置测试库基础数据，关键测试前后备份数据 |
| 部分异步消息问题偶现难以复现 | 高风险 | 完整打印MQ全链路日志，绑定全局TraceID，配合Jaeger链路追踪定位问题；加长压测时长复现概率性BUG |
| 新版本频繁迭代发布，测试版本混乱 | 中风险 | 每次发布标记唯一版本TAG，测试前核对版本号，非指定测试版本拒绝执行测试 |
